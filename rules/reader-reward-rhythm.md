# Reader Reward Rhythm

## 目标

分析小说时不能只说“节奏快/慢”，必须拆成读者奖励节拍：

```text
读者每隔多久获得一次新东西？
这个新东西是爽点、悬念、笑点、甜点、打脸、信息、反转，还是情绪补偿？
每次奖励之后，是否立刻抛出下一个问题？
```

## 一、读者奖励类型

| 奖励类型 | 读者感觉 | 常见实现 |
|---|---|---|
| 爽点 | 憋屈被释放 | 打脸、身份揭露、权力翻转、能力兑现 |
| 悬念 | 想知道答案 | 反常动作、秘密、危险倒计时、证据缺口 |
| 情绪补偿 | 心疼后被安慰 | 误会解除、迟来的保护、牺牲被看见 |
| 认知爽 | 原来如此 | 伏笔回收、真相开锁、时间线重组 |
| 羞辱点 | 替主角憋气 | 公共场合被压、被误解、被轻视 |
| 甜点 | 关系升温 | 反差关心、嘴硬保护、小动作照顾 |
| 危机点 | 不敢停 | 更坏结果、限制加重、选择变窄 |
| 争议点 | 想评论 | 道德困境、亲情绑架、谁对谁错 |

## 二、节拍不是固定字数，是密度设计

默认设计目标，可按平台调整：

```text
短视频/短剧脚本：30–90秒给一个小奖励，3–5分钟给一个大转折或大爽点。
公众号短小说：300–600字给一个小奖励，1200–2000字给一个大反转或强情绪释放。
长篇网文：每个小节必须有推进，每章至少有一个明确奖励点，章末必须留新问题。
```

这不是死规则，是检查工具：如果连续很长一段只有解释、回忆、心理描写，没有奖励，读者会走。

## 三、爽点不是喊爽，而是压迫后的释放

爽点公式：

```text
压迫越具体 → 读者越憋屈；
限制越明确 → 反击越有力；
反击越可见 → 爽感越直接；
代价越真实 → 爽点越不虚。
```

坏爽点：

```text
主角忽然变强，把所有人打脸。
```

好爽点：

```text
前面三次被人用账单羞辱；第四次主角没有吵，只把那张十年前的转账记录投到大屏上。
```

## 四、爽点类型库

| 类型 | 结构 | 风险 |
|---|---|---|
| 打脸爽 | 被误解/羞辱 → 证据出现 → 局势反转 | 铺垫不够会像开挂 |
| 身份爽 | 被轻视 → 身份暴露 → 对方失控 | 身份必须提前有痕迹 |
| 能力爽 | 被压制 → 技能兑现 → 解决难题 | 不要突然变强 |
| 真相爽 | 误会/悬疑 → 证据开锁 → 读者恍然 | 不能靠旁白公布答案 |
| 情绪爽 | 长期委屈 → 被看见/被选择 | 不能煽情过满 |
| 反杀爽 | 退无可退 → 利用对方规则反击 | 规则必须提前说明 |
| 牺牲返还 | 前面吃亏 → 后面成为关键筹码 | 吃亏不能白吃 |

## 五、读者奖励曲线

分析每章时，必须画出奖励曲线：

```text
0%：开场钩子，读者问题是什么？
10%：第一个压力或羞辱。
25%：第一次信息奖励或小反击。
40%：误导加深或危机升级。
60%：中段转折，读者原判断被动摇。
75%：强压迫或代价出现。
90%：爽点/真相/情绪释放。
100%：新问题或更大危机。
```

## 六、每个奖励点必须记录“成本”

没有成本的爽点很廉价。

记录：

```text
主角为了这个爽点付出了什么？
前面压了多久？
读者等待的是什么？
证据或能力是否提前出现？
爽点释放后，局势是否真的改变？
```

## 七、章节节奏检查

如果一章连续出现以下情况，就是拖：

- 只解释背景。
- 只写心理。
- 没有新信息。
- 没有新限制。
- 没有新选择。
- 没有可见代价。
- 没有悬念被打开或加深。
- 没有读者奖励。

## 八、奖励之后必须继续拉问题

读者奖励不能把故事讲完。正确结构：

```text
小爽点释放 → 暴露更大敌人；
小真相打开 → 发现更深秘密；
误会解除 → 出现更难选择；
身份揭露 → 关系代价变大。
```

只释放不加压，故事会松。

# PHASE386 — 正文生成 / 诊断隔离防火墙 V1

Status: FROZEN PROCESS DESIGN / NO FICTION GENERATED
Project: novel-distillation / 《一命过桥》
Highest accepted promotion checkpoint: Phase320（不变）

## 1. 本阶段解决什么

Phase374 已经证明：把“读者体验机制”直接当生成指令，会把观察规律变成可见的写作机器。
Phase377 又证明：AI味的主要风险不是某几个词，而是全局作者优化规律——每个局部都过度服务于理解、线索、转折与推进。
Phase385 再次复现：来源研究本身可以有效，但当跨书“翻页机制”被直接翻译成正文施工节拍时，真人读者报告 AI 味反而更重。

因此 Phase386 不改正文，只修流程：

`DIAGNOSIS KNOWLEDGE != AUTHORING INSTRUCTION`

## 2. 真人证据边界

本轮允许使用的实际真人原话只有：

- “能看。”
- “ai味道没有哈，反倒越来越重了。”

此前仓库中出现的“只是悬念让人有想看”不是用户实际说过的话，已经由单独的 evidence-correction receipt 标记为无效归因。不得用它证明 Phase385 的悬念/翻页驱动通过。

## 3. 三层隔离结构

### A. Coordinator / 协调层

协调层可以读取全部历史：

- Phase374 过度约束诊断；
- Phase377 AI味根因；
- Phase382/383/385 真人反馈；
- 来源蒸馏与读者驱动证据；
- 旧失败稿及已知失败位置；
- 目标读者画像与回归信息。

协调层的职责不是把这些规则塞进提示词，而是把当前故事事实压缩成一个最小、无答案键的作者包。

### B. Writer / 正文写作者层

写作者只能看到以下字段：

1. **固定故事身份**：题材、主角、必须保留的核心承诺/世界事实。
2. **当前视角人物**：谁在经历这场戏。
3. **场景起点**：当前地点、时间、身体状态、在场人物。
4. **已知关系事实**：只包含当前人物确实知道、且写这场戏必须知道的关系。
5. **当前直接欲望**：人物此刻自己想做什么。
6. **当前直接阻力**：什么真实约束挡住他。
7. **必要连续性事实**：不提供会造成硬逻辑错误的少量事实。
8. **长度与交付形式**：只规定短 pilot 的大致长度和中文小说文本。
9. **一般边界**：不得复制来源原文、不得模仿可识别作者风格。

写作者**不得看到**：

- Phase 编号和实验目标；
- “降低AI味”“提高翻页欲”“制造悬念”等优化指标；
- Phase374/377/383/385 的诊断标签；
- AI-F01 / AI-F03 / AI-F04 等分类；
- source-derived reader engine；
- beat A/B/C/D/E；
- “这里需要第三势力 / 关系反转 / 规则突破 / 悬念钩子”等施工要求；
- 技巧数量、段落比例、对白比例、目标节拍；
- 真人失败位置和具体批评；
- 前一版失败正文；
- 目标读者回归答案键；
- 来源小说名称、作者名以及任何“像某某写”的要求。

写作者的任务只有：**根据眼前人物和处境，写这一场真实发生的事。**

### C. Evaluator / 诊断层

只有在 writer 输出完成并冻结之后，诊断层才能读取：

- 冻结正文；
- Phase374/377/383/385 诊断资料；
- 真人历史反馈；
- 目标读者画像；
- 必要来源抽象机制。

诊断层只允许：

1. 定位当前文本里实际存在的问题；
2. 区分 AI 味、可读性、人物真实感、翻页欲、逻辑等不同维度；
3. 给出证据位置和诊断；
4. 判断是否值得送真人 pilot。

诊断层**禁止在同一次尝试里改写正文**。

## 4. 单向信息流

固定流程：

`FULL EVIDENCE -> COORDINATOR -> MINIMAL AUTHOR PACK -> FRESH WRITER -> FREEZE -> EVALUATOR -> HUMAN`

禁止：

`EVALUATOR RULES -> WRITER -> 按规则施工`

也禁止：

`WRITE -> EVALUATE -> 立刻把评价喂回同一 writer 继续修 -> 再评价`

这种循环容易迅速过拟合为“看起来很努力满足指标”的 AI 文。

## 5. Fresh context 要求

当前聊天已经读取过 Phase374、377、383、385 的诊断，因此**不能把当前聊天生成的新正文当成严格隔离的有效证明**。

下一次有效 pilot 必须由一个新的、未见上述诊断的新生成上下文执行。该上下文只读取最小 author packet。

当前聊天可以：

- 设计 author packet；
- 固化事实；
- 冻结任务；
- 在输出回来后进行 evaluator 审查；
- 记录真人结果。

当前聊天不作为 Phase387 的 blind writer。

## 6. Draft freeze

Phase387 中：

1. author packet 先冻结；
2. fresh writer 只读取 author packet；
3. 第一次完整输出立即冻结并记录 hash；
4. 冻结前不得读取 evaluator 诊断；
5. 冻结后不允许偷偷润色再给真人；
6. evaluator 可以先诊断，但不能替换正文；
7. 真人看到的必须是那份冻结稿。

这样才能知道“隔离生成”本身有没有作用。

## 7. Phase387 的最小测试边界

Phase386 不创建正文。

下一阶段若建立 Phase387，只允许：

- **1 个**短 pilot；
- 新 fresh writer context；
- 只读取最小 author packet；
- 不扩成长篇；
- 不做同一轮自动修复；
- 真人分别判断至少：
  - AI 味；
  - 是否想继续看；
  - 是否有明确停止/跳读位置。

任何一个短 pilot 的成功都不能自动授权全文重写。

## 8. 验收结论

Phase386 只证明：

- 生成和诊断的职责已经被重新隔离；
- writer 可见字段和隐藏字段已经明确；
- unsupported human attribution 已被隔离；
- Phase385 研究不会再直接充当 beat-by-beat 写作模板。

Phase386 **不证明**：

- AI味已经下降；
- Phase385 来源蒸馏已经成功转移到正文；
- Phase387 会成功；
- 可以扩成长篇；
- 可以推进 Phase320 accepted checkpoint。

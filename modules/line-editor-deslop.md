# 行文精修与去 AI 味模块

## 职责

在主线、因果、人物动机、连续性和场景结构已经稳定后，对正文进行逐句诊断与最小必要修改。

此模块只改变“怎么说”，不应暗中改变“发生了什么”。若发现结构或逻辑问题，必须退回对应阶段，不能用漂亮句子遮盖。

## 使用前置条件

满足以下条件后才能进入：

- 一句话主线稳定。
- 关键人物选择成立。
- 没有阻断级连续性冲突。
- 场景顺序不再大改。
- 高潮与结局方向已经确认。

若不满足，停止精修并说明应退回哪个阶段。

## Pattern-first：先找习惯，再找句子

不要把全文逐句标红。先识别 2—4 个反复出现、最伤害读感的习惯，再引用最典型位置。

### 1. 过滤与距离失控

警惕：

```text
他看见……
她感觉到……
我意识到……
```

这些词不是绝对错误。只有当场景需要更近的体验，而过滤词把读者隔开时才处理。

### 2. 解释重复

常见结构：

```text
动作或台词已经表达情绪。
下一句又解释人物很愤怒、很难过、终于明白。
再下一句总结这意味着什么。
```

优先删除重复解释，保留最有力的场内证据。

### 3. 抽象情绪与万能反应

警惕高频反应：

- 心口一沉
- 眼神复杂
- 深吸一口气
- 手指微微收紧
- 头皮发麻
- 嘴角勾起
- 眼底翻涌

不能机械替换成另一组动作。应根据人物、场景和物件寻找真正特有的反应；没有功能时直接删。

### 4. 句长单一

AI 味既可能来自通篇中长句，也可能来自通篇电报短句。

检查：

- 连续句子是否同样长度。
- 是否为了“节奏快”把一个完整动作拆成多句。
- 高潮是否需要短句落点。
- 推理、沉淀和复杂情绪是否被过度切碎。

句长应跟随场景任务，而不是服从固定比例。

### 5. 说明书式对话

检查人物是否在告诉对方双方都知道的事，真正服务对象其实是读者。

优先改为：

- 冲突中的信息泄露
- 物件或记录带出信息
- 一方故意试探，另一方回避
- 误解导致信息被错误解释

### 6. 声音漂移

检查：

- 叙述者是否突然变成作者评论。
- 所有人是否使用同样词汇和句式。
- 人物在愤怒、亲密、恐惧时的语言是否仍然完全一样。
- 题材语言是否被通用“网文腔”覆盖。

### 7. 假高级与意义尾巴

警惕：

- 命运、宿命、齿轮、篇章
- 仿佛、似乎、某种、说不清的大量重复
- “这一刻他终于明白”
- “真正重要的不是……”
- “这也许就是……”
- 章末总结、升华和预告片旁白

具体判断以文本功能为准，不使用单词黑名单机械删除。

### 8. 监控摄像头动作

连续记录拿起、放下、转身、走到、伸手等步骤，却没有视角、选择和压力。合并无功能动作，只保留改变读法的动作。

## 最小修改原则

1. 能删一句，不重写一段。
2. 能换一个具体词，不改整句。
3. 保留有效的别扭、停顿、口头习惯和不规整。
4. 不新增原文不存在的道具、情节、秘密或人物关系。
5. 不为去 AI 味故意制造错别字、病句和随机标点。
6. 不承诺任何 AI 检测百分比。

## 行文标记格式

每个问题包含：

```text
原句：
问题类型：
为什么伤害读感：
修改方向：
是否需要直接修改：是 / 否 / 退回结构阶段
```

需要直接重写时，先说明保留的事实和不可改变的边界，再给完整修改稿。

## 最终检查

- 是否还有作者替人物总结。
- 是否把动作后的同义心理解释删掉。
- 是否保留了人物独有的小动作和说话方式。
- 是否存在连续三段相同节奏。
- 是否存在为了显得高级而模糊具体关系的句子。
- 是否存在结尾总结主题而不是让场景自行落下。
- 是否因过度精简损失了必要心理、情绪余波或因果锚点。

## 输出模板

```md
# 行文精修报告

## 前置条件
通过 / 退回某阶段

## 最伤读感的反复习惯
1. 
2. 
3. 

## 典型位置

## 必须保护的作者声音

## 最小修改稿

## 修改后复核
```

## 禁止事项

- 不在结构未定时精修全文。
- 不把所有心理描写都改成动作。
- 不把所有句子都压短。
- 不用统一口语词把不同人物改成同一个人。
- 不以“更顺”为唯一目标；小说需要摩擦、潜台词和有意义的不完整。

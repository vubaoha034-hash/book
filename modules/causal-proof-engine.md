# 故事因果证明器

## 目标

证明故事不是靠作者拖着人物走，而是由事实、选择、后果和新限制连续逼出。

## 场景因果行

每个关键场景填写：

```text
场景：
前置事实：
人物此刻想要：
现实可选方案：
最简单合理方案：
为何不用最简单方案：
人物实际选择：
立即后果：
新获得 / 失去的信息：
新限制：
关系或权力变化：
如何逼出下一场：
删除本场会损失什么：
正文证据位置：
```

## 简单方案攻击

主动寻找能一击拆掉剧情的普通办法：

- 问清楚。
- 打电话或发消息核实。
- 直接离开。
- 报警、求医、求助或调监控。
- 拒绝签字、付款、赴约或开门。
- 使用已经拥有的资源、车辆、钥匙、证据或联系人。
- 把危险或真相告诉最该知道的人。

存在简单方案不一定是漏洞；但必须有已经写进故事的阻断：

- 时间来不及。
- 信息不完整或信息源不可信。
- 使用方案会触发更大代价。
- 身份、权力、证据、法律、身体或关系限制。
- 人物的错误认知已经由前文建立，并会付出代价。

“他当时没想到”“她太冲动了”不是充分解释，除非正文已用行为和历史证明，并让这个缺陷产生后果。

## 因果断裂等级

- `BLOCKER`：一个无明显成本的简单动作可解除核心危机。
- `MAJOR`：转折依赖人物暂时降智、巧合或未铺垫资源。
- `MINOR`：过程缺一处锚点，但补充不会改变场景设计。

## 压力升级测试

下一场必须至少发生一项：

- 选择更少。
- 代价更高。
- 时间更紧。
- 关系更坏。
- 对手权力更大。
- 新信息改变旧判断。
- 原方案失效。

若连续两场只是重复同一种羞辱、争吵、追逐或误会，判定为假推进。

## 高潮证明

高潮必须能沿表格倒推：

```text
高潮选择
← 前一场的新限制
← 更早的错误 / 承诺 / 损失
← 主角一直使用的生存策略
```

若删除中段仍能直接进入高潮，中段没有参与因果。

## 输出

先列阻断级断点，再给完整场景链。不要用“因此/但是”字样本身冒充真实因果；必须写出具体事实和代价。

# Workflow 05 — Deep Story Dissection

## Goal

把一本小说或一章内容拆成“可复制的叙事机器”，不是泛泛总结。

## Trigger

用户要求：

- 分析这本书为什么好看。
- 分析悬疑怎么布置。
- 反转在哪里。
- 爽点在哪里，多久一次。
- 这本书的逻辑如何推进。
- 按爆款小说拆解方式分析。

## Output Order

### 1. 一句话读者承诺

```text
这篇作品让读者追下去的主要承诺是：
悬疑 / 爽感 / 情绪补偿 / 关系撕裂 / 复仇 / 生死危机 / 道德争议 / 认知爽
```

### 2. 悬疑地图

必须回答：

```text
第一个悬疑在哪里出现？
读者第一个问题是什么？
作者给了哪些真线索？
给了哪些误导？
什么时候第一次开锁？
开锁后是否打开更大的锁？
最终真相回收了哪些细节？
```

### 3. 伏笔账本

用表格列出：

```text
伏笔 / 表层意义 / 真实意义 / 回收位置 / 是否公平
```

### 4. 反转账本

每个反转都必须写清：

```text
反转前读者以为：
反转后读者发现：
它改变了什么：理解 / 选择 / 代价 / 权力 / 情绪
是否有提前铺垫：
是否带来新压力：
```

### 5. 爽点和奖励节拍

必须统计：

```text
多少字/多少场出现一个小奖励？
多少字/多少场出现一个大转折？
奖励类型分别是什么？
读者最爽的一刻来自哪里？
前面压了多久？
主角付出了什么成本？
```

### 6. 逻辑推进链

```text
事件 → 选择 → 代价 → 新信息 → 新限制 → 反转/奖励 → 新问题
```

不能只写剧情梗概。要写因果。

### 7. 人物发动机

```text
人物想要什么？
他怕什么？
他藏了什么？
他误解了什么？
他每一次选择付出了什么？
```

### 8. 去 AI 味来源

这篇作品像真人写的地方来自哪里：

- 具体物件。
- 不完美反应。
- 现实摩擦。
- 关系里的别扭。
- 情绪不直接说。
- 信息不一次讲完。

### 9. 可复用规则

最后必须生成 10–30 条可执行规则。

每条规则必须是：

```text
以后写作时可以直接执行的动作
```

不能写空话，比如“增强悬念”“提升爽感”。要写成：

```text
在揭露真相前，先让一个小物件出现两次：第一次有生活解释，第二次有异常解释，第三次才开锁。
```

## Scoring

| Dimension | Weight |
|---|---:|
| 悬疑锁钥设计 | 20 |
| 伏笔公平度 | 15 |
| 反转有效性 | 15 |
| 爽点/奖励密度 | 15 |
| 因果逻辑 | 15 |
| 人物发动机 | 10 |
| 去 AI 味细节 | 10 |

## Final Requirement

任何分析必须落到“我下次怎么写”。如果不能转成写作动作，说明分析还不够深。

# 小说总控生产流程 V2

## 目标

把一个模糊创意或已有稿件，经过独立的结构、人物、读者、逻辑和语言阶段，推进到可交付成稿。

本流程的重点不是一次性生成完整小说，而是避免以下失败：

- 主线没定就开始扩写。
- 节奏问题靠删描写解决，结果只剩事件提纲。
- 作者一边写一边证明自己写得对。
- 为了反转临时增加规则和道具。
- 逻辑问题与去 AI 味同时修改，造成新漏洞。
- 每轮修改都解决局部，却破坏整体。

## 目录建议

每个小说项目建议建立：

```text
作品名/
├── 00-story-contract.md
├── 01-structure-map.md
├── 02-character-state.md
├── 03-scene-plan.md
├── 04-draft.md
├── reviews/
│   ├── opening-retention.md
│   ├── beta-reader-panel.md
│   ├── continuity-report.md
│   ├── developmental-report.md
│   └── line-edit-report.md
├── revision-ledger.md
└── final.md
```

## Phase 0：故事契约

### 输入

用户创意、旧稿、题材方向或一句话设定。

### 产出

```text
题材与平台：
目标篇幅：
目标读者：
目标情绪：
一句话读者承诺：
一句话主线：
主角想要：
持续阻力：
失败代价：
为什么必须现在解决：
核心关系：
不可逆事件：
结局兑现：
禁止改变的设定：
```

### Gate 0

以下任一项不成立，不进入正文：

- 主线无法一句话说清。
- 主角没有主动欲望。
- 阻力只是抽象“命运”。
- 失败没有具体损失。
- 开头与结局没有同一个核心问题。

## Phase 1：结构设计

加载：

- `modules/developmental-editor.md`
- `rules/novel-logic-checklist.md`
- 需要悬疑时加载 `rules/suspense-reversal-payoff.md`
- 需要商业节奏时加载 `rules/reader-reward-rhythm.md`

建立场景链：

```text
场景编号：
人物目标：
阻力：
行动：
失败 / 成功但代价更大：
新信息：
关系或权力变化：
逼出的下一场：
```

### Gate 1

- 每个场景结束后必须有状态变化。
- 关键场景主要由因果连接。
- 中段不能只重复同一种受压。
- 高潮必须由前面选择逼出。
- 结局必须兑现读者承诺。

## Phase 2：人物压力测试

加载：

- `modules/character-pressure-test.md`
- `rules/reader-trust-and-economy.md`

对所有关键选择执行：

- 当前欲望
- 当前恐惧
- 当前知识
- 可选方案
- 最简单合理方案
- 未选择原因
- 选择代价
- 对下一场的影响

### Gate 2

出现以下情况必须退回结构阶段：

- 人物只能靠降智进入下一场。
- 人物提前知道秘密。
- 关系无代价地突然改变。
- 反派明知明显风险却无理由忽略。
- 主角突然获得未建立的能力或资源。

## Phase 3：正文写作

### 写作上下文限制

每次只提供：

1. 故事契约。
2. 当前场景计划。
3. 当前人物状态。
4. 当前场景必须使用的设定。
5. 项目文风基线。
6. 前一场结尾和后一场目标。

不要同时加载完整读者面板、连续性清单、发展性编辑清单和去 AI 词库。

### 每场写后记录

```text
已发生事实：
人物新获得的信息：
人物状态变化：
物件状态变化：
关系变化：
未回收问题：
下一场被什么逼出：
```

## Phase 4：开篇留存冷读

加载：

- `modules/opening-retention-reader.md`

只读前 30—60 字、前 150—300 字和第一场戏。

### Gate 4

- 有具体问题，不只是气氛。
- 前 150—300 字形成基本困境。
- 第一场戏发生有效变化。
- 没有未被作者有意识接受的致命停止点。

失败时只重做开头相关场景，不顺手改全文。

## Phase 5：独立读者面板

加载：

- `modules/beta-reader-panel.md`

四个读者先独立完成报告，再汇总。

### Gate 5

必须处理：

- 多个读者在同一位置滑读或离开。
- 单个读者发现确定性逻辑断裂。
- 多个读者都未感受到预定情绪。
- 类型承诺与实际内容冲突。

不强改：

- 仅一个读者的纯口味偏好。
- 与作品明确意图相反的模板要求。

## Phase 6：连续性与逻辑审查

加载：

- `modules/continuity-editor.md`

建立事实、时间、物件、知识和规则表，逐场交叉检查。

### Gate 6

- 不允许保留未解释的确定性冲突。
- 高风险疑点必须由作者确认是伏笔还是错误。
- 关键规则必须有触发条件、限制和成本。
- 关键道具必须有来源和状态。
- 关键选择必须回答“为什么不用更简单办法”。

## Phase 7：发展性编辑复审

再次加载：

- `modules/developmental-editor.md`

这次基于完整正文，不看作者自评分数。只给出 2—5 个根部问题，并标出必须保护的有效部分。

### Gate 7

阻断级和重大级问题未解决，不进入语言精修。

## Phase 8：修改总账

把所有报告合并到 `revision-ledger.md`，按以下顺序排序：

1. 主线与结局
2. 因果与人物选择
3. 连续性与世界规则
4. 场景功能与节奏
5. 信息控制与情绪兑现
6. 行文与 AI 味
7. 标点和错字

每条记录：

```text
问题编号：
来源报告：
严重等级：
位置：
根因：
修改动作：
受影响章节：
必须保护：
修改状态：待处理 / 已修改 / 已验证 / 有意保留
验证证据：
```

## Phase 9：行文精修与去 AI 味

加载：

- `modules/line-editor-deslop.md`
- `rules/no-ai-smell.md`
- `rules/reader-trust-and-economy.md`

执行 Pattern-first 精修，优先修改最反复、最伤读感的 2—4 类习惯。

### Gate 9

- 不得因润色改变情节事实。
- 不得因压缩删除因果锚点、伏笔或情绪余波。
- 不得把人物声音统一成通用网文腔。
- 不得用语言修复掩盖未解决的结构问题。

## Phase 10：最终冷读

重新进行：

1. 开篇留存测试。
2. 手机沉浸读者单独通读。
3. 连续性定向复核，只检查修改过的位置及其连锁影响。
4. 结局兑现检查。

## 最终交付内容

```text
最终正文
一句话主线
目标情绪是否兑现
已解决的阻断级问题
有意保留的争议点
仍存在但可接受的风险
自评分与评分依据
```

自评分不得早于全部审查完成，也不得只给数字。

## 快速模式

当用户只要求修改一段或一章时，可使用缩短流程：

```text
故事契约摘要
→ 当前场景结构
→ 人物选择检查
→ 修改正文
→ 开篇/读者冷读（按范围）
→ 连续性检查
→ 行文精修
```

不得因为任务短就跳过逻辑检查。

## 推翻重写模式

当用户明确要求“全部推倒重写”时：

1. 保留用户指定的核心关系、主线和结局约束。
2. 旧稿只作为失败案例，不沿用其场景顺序。
3. 重新执行 Phase 0—2。
4. 新大纲通过后再写正文。
5. 不在旧稿上继续打补丁。
